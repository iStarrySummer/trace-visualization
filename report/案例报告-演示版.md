# 案例报告（演示数据版，不能作为正式实证结论提交）

本原型研究结构化反思提示与 AI Coding 错误恢复效率之间的关系，演示数据覆盖数据清洗、批量文件处理和图表调试三类任务，并比较直接提示与计划—执行—测试—反思两种策略。系统把一次运行表示为行为序列，同时计算首次通过率、最终完成率、错误恢复率、修复轮次、工具调用和时长；使用路径图解释“如何恢复”，使用任务×策略矩阵和效率散点解释“在哪些条件下更稳定”，再用时间线与日志详情核查个案。

交互分析采用 UWData 课程所示的 Vega-Lite 组合、数据变换与选择语法。时长—修复代价探索器以 `vconcat` 连接概览直方图和细节散点图，以 `layer` 叠加运行点、策略回归趋势、最近点悬停和最终状态形状，并用区间 Brush & Link（刷选联动）缩小观察范围；任务完成率视图先 `aggregate` 再 `facet`，以共享纵轴比较三类任务，并用分层文字直接显示比例；多变量分布视图用 `repeat` 重复时长、修复轮次和工具调用规范，再用交集选择同时约束多个范围。淡粉 `#E8A0B2` 固定表示直接提示，淡蓝 `#94C4E2` 固定表示结构化反思，使同一策略在所有图中保持视觉身份；状态还配有形状和文字，因此结论不依赖颜色单一通道。

当前页面中的数字来自固定随机种子的模拟器，只用于验证筛选、联动和叙事结构。正式报告应把本节替换为真实统计输出，并至少写出两条一/二维发现、两条同时涉及任务类型—提示策略—错误类型—结果的多变量发现，以及一条循环修复或异常终止个案；每条发现都要给出样本量、筛选条件和对应视图。若真实数据没有显著差异，也应如实报告，而不是调整规则追求预期结论。

局限性至少包括小样本导致的不稳定性、模型输出随机性、行为分类中的主观判断、网页端元信息缺失，以及任务难度无法完全等价。即便结构化策略在样本中伴随更高成功率，也不能据此宣称提示策略导致性能提升；更稳妥的表述是“在本实验设置与样本中观察到相关差异，仍需更大样本和预注册设计复核”。
