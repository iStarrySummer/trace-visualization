# 采集与标注手册

## 实验单元与提示模板

一个 `run_id` 表示“一个模型在一种提示策略下完成一个固定任务的一次独立运行”。直接提示只包含任务背景、输入和可执行验收条件，不要求过程格式；结构化反思提示在相同任务信息后增加“先给计划，再执行；每次测试失败后先解释错误类型与根因，再修改并重测；通过或达到上限后总结”。两种策略必须使用同一模型版本、温度、工具权限、初始文件与测试，运行顺序随机化，每次运行之间重置上下文。

## 推荐样本量

三类任务各准备 3 个题目，每题每种策略重复 4 次，共 3×3×2×4=72 次运行。按每次至少保留 task、assistant、tool 三类消息计算，理论下限为 216 条，超过题目要求的 150 条；若某次没有工具消息，也应保留完整对话并在缺失说明中记录原因。先做每格 1 次的 18 次预实验，只有字段与测试稳定后才开始正式采集。

## 原始数据格式

原始 JSONL 每行是一条消息或工具事件，最少包含 `timestamp`、`task_id`、`task_type`、`run_id`、`turn_id`、`role`、`content`、`model`、`prompt_variant`、`event_type` 和 `result`。`error`、`response_time`、`token_usage`、`tool_call`、`tool_input`、`tool_output` 无法取得时保留为 null，不允许用 0 伪装未知值。`event_type` 可以在采集后由规则初标，但正式分析前必须抽检。

## 行为与错误编码

行为类别采用互斥的主标签：接收任务、规划、生成代码、执行工具、检测错误、诊断、修复、验证、完成、终止、澄清。错误类别采用 SyntaxError、TypeError、AssertionError、FileNotFound、DataSchema、Dependency、Network/API、Logic 和 Other；分类顺序从明确异常名到语义规则，无法确定则标记 Other，不能为了图表整齐强行猜测。两名成员独立标注同一批至少 30 条含错误样本，计算一致率并讨论分歧；最终规则版本写入报告。

## 匿名化与伦理

采集前只使用小组成员自愿产生的任务，不纳入第三方私密对话；原始文件保持只读备份，不上传公开仓库。清洗副本需要替换姓名、学号、邮箱、电话、绝对用户目录、API Key 和访问令牌，代码中的公开包名、函数名和测试失败信息可保留。页面日志详情只加载匿名化后的文本，正式演示前随机抽查至少 30 条内容，并在报告中列出自动规则覆盖不到的风险。
